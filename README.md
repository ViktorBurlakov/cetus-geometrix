# 📚 Architecture and Key Principles of Geometrix

## 1. Constructive Solid Geometry (CSG)

The Geometrix library utilizes the **Constructive Solid Geometry (CSG)** approach to model complex 2D cross-sections. This pattern ensures flexibility and data immutability:

### A. The CSG Tree Structure
Geometry is represented as a binary tree where:
* **Leaves (Primitives):** The atomic, base geometric shapes (`Rectangle`, `Polygon`). These are calculated **analytically** where possible.
* **Nodes (Compounds):** Composite objects representing the results of boolean operations (`Union`, `Difference`, `Intersection`). These are typically calculated **numerically**.

### B. Immutability Principle
* All geometric objects (`GeometryObject`) are **immutable**.
* Any operation (e.g., `translate`, `rotate`, or a boolean operation) returns a **new Compound object**, ensuring the integrity and traceability of the data structure.

## 2. Hybrid Calculation Approach and Delegation

Geometrix combines precise analytical methods with robust numerical methods for calculating inertial properties.

### A. Hybrid Calculations
1.  **Analytical (Precision):** Used for simple primitives (`Rectangle`) using exact mathematical formulas for maximum precision.
2.  **Numerical (Robustness):** Used for arbitrary polygons (`Polygon`) and the results of complex CSG operations. The **Gauss-Green formula** is employed for contour integration, ensuring reliable results even with complex or irregular contours generated by boolean operations.

### B. The Delegation Principle
Calculation logic is strictly separated from the data structure:
* **Compound (Node):** Stores references to the operands (`left`, `right`) and the operation object (`CSGOperation`).
* **CSGOperation (Logic):** Serves as the delegation core. It handles property calculations (`sums`, `centroid`) by determining the most appropriate method: whether to use a simple additive sum (if operations like `Union` don't overlap) or robust contour integration (for complex overlaps, `Difference`, or `Intersection`).

## 3. The Final Properties Model (`Centroid`)

The end result of all geometric and inertial calculations is encapsulated in the **`Centroid`** object.

### A. Core of Center of Mass (CM)
The **`center`** coordinates (Center of Mass) define the only point in the cross-section where the **static moments are zero** ($S_x^c = 0, S_y^c = 0$).

### B. Inertia Minimality
* The `Centroid` object contains the **Centroidal Inertia Tensor** ($I_{xx}^c, I_{yy}^c, I_{xy}^c$).
* These moments are **ALWAYS MINIMAL** (due to Steiner's Theorem) and are mandatory for accurate engineering calculations such as bending stress ($\sigma = M \cdot y / I$) and structural stability (buckling).
