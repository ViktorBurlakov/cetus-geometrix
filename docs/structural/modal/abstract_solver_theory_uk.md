# 📚 Теорія: Абстрактний Ітераційний Вирішувач (`abstract_solver.py`)

## 1. Призначення та Архітектурний Патерн
Модуль `abstract_solver.py` визначає **абстрактний базовий клас `AbstractIterativeSolver`**. Цей клас є наріжним каменем для всіх чисельних вирішувачів (солверів) у проекті, які використовують ітераційний підхід для знаходження розв'язку.

Він реалізує патерн **Стратегія (Strategy)** в архітектурі **Task-Solver-Results**:
* **Солвер** (як стратегія) інкапсулює алгоритм *як* розв'язати задачу.
* Він приймає **Задачу (Task)** (як контекст), яка визначає *що* розв'язати.
* Солвер повертає **Результати (Results)**.

Абстрактний клас забезпечує уніфікований інтерфейс для запуску розрахунків (`execute`) та визначає спільні атрибути (параметри задачі), які є необхідними для будь-якого ітераційного методу.

## 2. Дженерики та Гнучкість
Клас `AbstractIterativeSolver` є **дженериком** (`Generic[TaskType, ResultType]`). Це означає, що він може працювати з різними типами задач (`TaskType`) та повертати різні типи результатів (`ResultType`), за умови, що вони відповідають певним базовим вимогам:
* `TaskType` має бути сумісним з `AbstractStructuralTask`.
* `ResultType` має бути сумісним з `BaseModel` (для забезпечення структурованих результатів).

Це забезпечує високу гнучкість та можливість повторного використання коду для різних інженерних задач.

## 3. Ключові Атрибути та Абстрактні Методи

### 3.1. Атрибути (Ініціалізація)

| Атрибут | Призначення | Джерело |
| :--- | :--- | :--- |
| `task_context` | Об'єкт, що містить усі вхідні дані та параметри, специфічні для поточної задачі. | Надається при інстанціюванні солвера. |
| `section_data` | Дискретизовані структурні властивості елемента (маса, жорсткість), необхідні для розрахунку. | Витягується з `task_context.model_data`. |
| `max_iter` | Максимальна кількість ітерацій, дозволена для солвера. | Витягується з `task_context.max_iter`. |
| `tolerance` | Критерій збіжності, що визначає необхідну точність результату. | Витягується з `task_context.tolerance`. |

### 3.2. Абстрактні Методи (Для Реалізації в Підкласах)

| Метод | Призначення |
| :--- | :--- |
| `perform_iteration(*args, **kwargs) -> tuple` | **Обов'язкова реалізація**. Цей метод відповідає за виконання **одного кроку** ітераційного алгоритму. Підкласи повинні визначити конкретну логіку обчислень для кожної ітерації. Повертає оновлений стан та показник помилки. |
| `execute() -> ResultType` | **Обов'язкова реалізація**. Цей метод керує **повним циклом розрахунку**: запускає ітерації, перевіряє умови збіжності та формує кінцевий об'єкт результатів. |

Така структура дозволяє створювати різні солвери, кожен з яких реалізує свій унікальний чисельний метод, але всі вони дотримуються спільного інтерфейсу та обробляють дані у стандартизований спосіб.
